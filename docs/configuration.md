# Конфигурация Abdal 4iProto Server

Конфигурация сервера Abdal 4iProto строится на трех файлах формата JSON:
1. [`server_config.json`](#1-конфигурация-сервера-server_configjson) — глобальные настройки демона, портов, сетевых таймаутов и протокола DNSTT.
2. [`users.json`](#2-конфигурация-пользователей-usersjson) — база пользователей, роли, ограничения скорости, квоты трафика, списки фильтрации и политики сессий.
3. [`blocked_ips.json`](#3-глобальный-черный-список-blocked_ipsjson) — глобальный черный список IP-адресов.

---

## 1. Конфигурация сервера (`server_config.json`)

Файл располагается в корне рабочей директории сервера (`/usr/local/abdal-4iproto-server/server_config.json`).

### Полный пример конфигурации

```json
{
  "ports": [64235, 64236, 64237],
  "shell": "/bin/bash",
  "max_auth_attempts": 3,
  "server_version": "SSH-2.0-Abdal-4iProto-Server",
  "private_key_file": "id_ed25519",
  "public_key_file": "id_ed25519.pub",
  "evict_on_max_sessions": true,
  "udp_idle_timeout_seconds": 120,
  "udp_socket_buffer_kb": 4096,
  "dnstt_enabled": false,
  "dnstt_listen": "0.0.0.0:53",
  "dnstt_resolver": "",
  "dnstt_nameserver": "t.example.com",
  "dnstt_public_key": "",
  "dnstt_psk": "",
  "dnstt_max_sessions_per_ip": 8,
  "dnstt_idle_timeout_seconds": 60
}
```

### Справочник параметров `server_config.json`

| Параметр | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `ports` | `[]int` | `[2222]` | Список портов TCP, на которых сервер слушает подключения одновременно. Валидный диапазон: `1` – `65535`. |
| `shell` | `string` | `"/bin/bash"` | Командная оболочка для пользователей с ролью `admin` (`/bin/bash` на Linux, `cmd.exe` или `powershell.exe` на Windows). Обычным пользователям доступ к shell заблокирован. |
| `max_auth_attempts` | `int` | `3` | Порог неудачных попыток входа с одного IP-адреса, после которого IP временно блокируется модулем Guard. |
| `server_version` | `string` | `"SSH-2.0-Abdal-4iProto-Server"` | Строка баннера версии SSH, отдаваемая клиенту при рукопожатии. |
| `private_key_file` | `string` | `"id_ed25519"` | Относительный или абсолютный путь к файлу приватного SSH-ключа хоста. |
| `public_key_file` | `string` | `"id_ed25519.pub"` | Относительный или абсолютный путь к файлу публичного SSH-ключа хоста. |
| `evict_on_max_sessions` | `bool` | `false` | **Глобальная политика вытеснения:** `true` — при достижении лимита сессий старая зависшая сессия завершается в пользу нового подключения; `false` — новое подключение отклоняется. |
| `udp_idle_timeout_seconds`| `int` | `120` | Таймаут бездействия UDP-ассоциации (в секундах), после которого буфер освобождается. |
| `udp_socket_buffer_kb` | `int` | `4096` | Размер сокетного буфера для UDP-пакетов в килобайтах (4096 КБ = 4 МБ). |
| `dnstt_enabled` | `bool` | `false` | Активация DNSTT-сервера для обхода блокировок через DNS туннель. |
| `dnstt_listen` | `string` | `":53"` | Сетевой адрес и UDP-порт прослушивания DNSTT (например, `0.0.0.0:53` или `:5353`). |
| `dnstt_nameserver` | `string` | `""` | Делегированное доменное имя для входящих DNS-запросов (NS-запись). |
| `dnstt_public_key` | `string` | `""` | Публичный ключ Noise-handshake для DNSTT-клиента. |
| `dnstt_psk` | `string` | `""` | Pre-Shared Key (дополнительный симметричный секрет) для DNSTT. |
| `dnstt_max_sessions_per_ip`| `int` | `8` | Максимальное число одновременных DNSTT-туннелей с одного внешнего IP. |
| `dnstt_idle_timeout_seconds`| `int` | `60` | Таймаут неактивности сессии DNSTT в секундах. |

## 2. Конфигурация пользователей (`users.json`)

Файл содержит массив учетных записей. Для каждого пользователя могут быть заданы индивидуальные квоты, ограничения скорости и списки фильтрации.

### Пример конфигурации `users.json`

```json
[
  {
    "username": "admin",
    "password": "SuperSecretAdminPassword123!",
    "role": "admin",
    "max_sessions": 2,
    "session_ttl_seconds": 86400,
    "max_speed_kbps": 0,
    "max_total_mb": 0,
    "blocked_domains": [],
    "blocked_ips": [],
    "log": "yes"
  },
  {
    "username": "mob_1",
    "password": "PasswordForMobileUser_2026",
    "role": "user",
    "max_sessions": 1,
    "session_ttl_seconds": 86400,
    "evict_on_max_sessions": true,
    "max_speed_kbps": 10240,
    "max_total_mb": 51200,
    "blocked_domains": [
      "*.tiktok.com",
      "facebook.com",
      "*.facebook.com"
    ],
    "blocked_ips": [
      "10.0.0.*",
      "192.168.*.*"
    ],
    "log": "no"
  }
]
```

### Справочник полей учетной записи пользователя

| Поле | Тип | Обязательное | Описание |
| :--- | :--- | :--- | :--- |
| `username` | `string` | Да | Уникальный логин пользователя для SSH-аутентификации. |
| `password` | `string` | Да | Пароль пользователя в открытом виде. |
| `role` | `string` | Нет (по умолчанию `user`) | Роль пользователя: `"admin"` или `"user"`. Значение регистронезависимо (`Admin` = `admin`). |
| `max_sessions` | `int` | Нет (по умолчанию `1`) | Максимальное количество одновременно активных SSH-сессий. |
| `session_ttl_seconds` | `int` | Нет (по умолчанию `86400`) | Время жизни сессии в секундах (86400 = 24 часа), после которого сессия считается истекшей. |
| `evict_on_max_sessions` | `bool` / `null` | Нет | **Индивидуальное переопределение вытеснения:**<br>• `true` — всегда вытеснять старую сессию пользователя при нехватке слотов.<br>• `false` — никогда не вытеснять (отклонять новое подключение).<br>• Не указано / `null` — наследует значение `evict_on_max_sessions` из `server_config.json`. |
| `max_speed_kbps` | `int` | Нет (по умолчанию `0`) | Ограничение пропускной способности в Килобайтах/сек (например, `10240` = 10 МБ/с). `0` — без ограничений. |
| `max_total_mb` | `int` | Нет (по умолчанию `0`) | Лимит суммарного трафика в Мегабайтах (входящий + исходящий). `0` — безлимитный трафик. При превышении квоты новые туннели отклоняются. |
| `blocked_domains` | `[]string` | Нет | Список запрещенных доменных имен. Поддерживает маски wildcard (например, `*.instagram.com`, `ads.*`). |
| `blocked_ips` | `[]string` | Нет | Список запрещенных целевых IP-адресов. Поддерживает маски wildcard (`10.0.0.*`, `172.16.*.*`). |
| `log` | `string` | Нет (по умолчанию `"no"`) | `"yes"` — вести подробный журнал сетевых запросов пользователя в `users_log/<username>.log`; `"no"` — не вести. |

> [!NOTE]
> **Различия между ролями `admin` и `user`:**
> - Пользователь с ролью `admin` получает доступ к интерактивной оболочке shell (`/bin/bash`), может выполнять команды на сервере, и для него **не действуют** ограничения `blocked_domains` и `blocked_ips`.
> - Пользователь с ролью `user` изолирован: доступ к shell заблокирован (при попытке открыть терминал соединение отклоняется с сообщением `Interactive shell is disabled for standard users`), разрешены только каналы туннелирования `direct-tcpip` и `direct-udpip`.

## 3. Глобальный черный список (`blocked_ips.json`)

Файл содержит глобальный черный список IP-адресов клиентов, которым запрещено даже устанавливать соединение с сервером (фильтрация на уровне TCP-рукопожатия Guard).

```json
{
  "blocked": [
    "198.51.100.4",
    "203.0.113.*",
    "192.0.2.15"
  ]
}
```

Клиент, чей IP совпадает с записью из черного списка, немедленно сбрасывается с записью в лог безопасности.

## 4. Рекомендации по оптимизации конфигурации

### Мобильные клиенты (Android / iOS)
Мобильные клиенты часто меняют сеть (LTE ↔ Wi-Fi, переключение между вышками сотовой связи). При этом операционная система клиента открывает новое TCP-соединение, а старое зависает в статусе `ESTABLISHED` на сервере до истечения таймаутов TCP Keepalive.
- Обязательно выставляйте:
  ```json
  "evict_on_max_sessions": true
  ```
  Это гарантирует, что телефон мгновенно восстановит связь, вытеснив зависшую сессию без ручного ожидания.

### Защита от переполнения диска логами
Если пользователей много, не включайте параметр `"log": "yes"` для всех учетных записей без настроенной ротации. Оставляйте аудит включенным только для отладки или критичных учеток.
